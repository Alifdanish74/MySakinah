# Antislop UI audit 001

Scope: `apps/admin` dashboard overview, shared navigation, submission table, and related dialogs.
Priorities follow antislop rule tiers: Hard Gate is HIGH, Purpose-Gate is MEDIUM, Quality Locks is LOW.

## Findings

1. **HIGH | R-27, C-4 | Database failures are shown as valid empty or zero data.** The overview turns submission-count failures into `0`, while the module page ignores returned query errors and catches failures by replacing records with an empty list. This hides outages and can mislead admins about actual submissions. (`apps/admin/src/app/(dashboard)/page.tsx:28-38`; `apps/admin/src/app/(dashboard)/[module]/page.tsx:46-59`)

2. **HIGH | R-32, R-39 | Mobile navigation and dialogs are not fully keyboard-accessible.** The closed mobile sidebar is only translated off-screen, so its links remain in the DOM and can receive keyboard focus; its trigger also omits expanded state. Edit, filter, and delete dialogs use generic containers without dialog semantics, Escape handling, or focus management. (`apps/admin/src/components/sidebar.tsx:55-70`; `apps/admin/src/app/globals.css:391-405`; `apps/admin/src/components/header.tsx:53-59`; `apps/admin/src/components/edit-modal.tsx:177-190`; `apps/admin/src/components/filter-modal.tsx:135-145`; `apps/admin/src/components/delete-dialog.tsx:43-56`)

3. **HIGH | R-39 | Form labels are not programmatically connected to their fields.** The shared `Label` and `Field` helpers render labels without `htmlFor` or wrapping the associated input, so visible labels in the edit and filter forms do not provide reliable accessible names. (`apps/admin/src/components/edit-modal.tsx:17-35`; `apps/admin/src/components/filter-modal.tsx:76-86`)

4. **HIGH | R-02 | UI copy contains em dash characters.** Filter options, missing-value placeholders, and the document title include em dashes, which the rule forbids in agent-written text. (`apps/admin/src/components/filter-modal.tsx:202-233`; `apps/admin/src/lib/utils.ts:70-121`; `apps/admin/src/app/layout.tsx:14-15`)

5. **HIGH | R-03 | Several touch targets are smaller than 44 pixels.** Table row actions are set to 30 pixels high, pagination to 36 pixels, and shared ghost buttons to 40 pixels; these are difficult to use on touch screens and below the required minimum. (`apps/admin/src/components/submission-table.tsx:884-893,1036-1045,1073-1083`; `apps/admin/src/app/globals.css:161,183`)

6. **HIGH | R-36, R-38 | The dashboard makes unverified operational claims.** “SYSTEM OPERATIONAL” and “real-time” submissions are presented without a health check or live-update mechanism shown in the page implementation. (`apps/admin/src/app/(dashboard)/page.tsx:67-74`)

7. **HIGH | R-37 | A design direction is missing before the requested revamp.** There is no `DESIGN.md` or explicit brand/style brief in the workspace, and the current interface does not declare the required ENERGY, RHYTHM, and MOTION dials. The owner needs to set direction before visual changes are made. (`apps/admin/src/app/globals.css:1-20`; `apps/admin/src/app/(dashboard)/page.tsx:54-63`)

8. **MEDIUM | R-01, R-10, R-12, R-13, R-14 | Visual effects and repeated cards have no stated purpose.** The overview and module cards combine blue-purple gradients, blur, glow, shadows, and a repeated card treatment without documented brand or hierarchy reasons. (`apps/admin/src/app/(dashboard)/page.tsx:54-63`; `apps/admin/src/components/module-card.tsx:49-92`)

9. **LOW | R-21 | The admin UI is dark-only without a documented reason or theme choice.** The theme is hard-coded as dark, and no light/dark control is present in the admin UI. (`apps/admin/src/app/globals.css:7-20`; `apps/admin/src/components/dashboard-shell.tsx:47-73`)
